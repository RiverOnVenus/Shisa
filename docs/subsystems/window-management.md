# Window management

## Hiding and restoring windows

The session agent and its KWin script manage windows that are already open. The script matches protected apps by `desktopFileName` first and `resourceClass` second. It minimizes locked windows, sets their opacity to zero, and removes them from the taskbar, switcher, and pager. Restoration affects windows Shisa hid and preserves ordinary user minimization. When the last app is unprotected, the agent restores its windows before unloading the script.

The agent builds versioned window state from `ListApps` and `WindowStates`. The script reads it over the session bus every 250 milliseconds and applies visibility and activation changes in place. Initial startup or loss of contact can trigger a fresh `loadScript` and `run`. The agent uses separate session-bus connections for KWin calls and acknowledgements, assigns a unique plugin name, and waits for the new script's acknowledgement before unloading the old one. The agent accepts `WindowsChecked`, `HiddenWindows`, `WindowEvent`, and `RestoreIfTicketed` only from the current owner of `org.kde.KWin`. It ignores a `WindowsChecked` generation above the one it last published. `WindowState` and `HiddenApps` are read-only. `RestoreWindow`, `VerifyLock`, and `VerifyLockReport` come from the restore panel or the CLI, and restoration still passes the daemon's ticket or polkit check.

Window allowance is separate from a launch ticket. Ticket expiry affects the next launch. Manual `Lock` and the configured screen-lock policy revoke both states. A successful authenticated launch, `shisa unlock`, an allowed autostart, or a launch covered by a valid ticket sets window allowance. A daemon restart clears it, and an agent restart reads it back from the daemon.

The agent holds one system-bus connection for its registration, shisad's signals, and its daemon checks. A shisad restart keeps that connection, and the agent registers again when the name returns. If the connection itself closes, the agent exits so the user unit restarts it with fresh connections and match rules. `Restart=on-failure` cannot help while the process keeps running on a dead connection.

The script reports focus changes. The agent times focus loss using `RelockSeconds`, cancels the timer on refocus or lock, and checks focus again before calling `Hide`. `Hide` drops the window permission but keeps the app's launch ticket, so a focus-loss hide does not end the grace period. The first focus-loss hide in an agent run sends a notification that the window was hidden and that a left-click on the tray opens the restore panel. Later hides stay silent, and the locked tray icon carries the state. Restoring the window calls `Unhide`, which needs no authentication while the ticket is still valid and asks for one after it expires or after a manual lock, or a screen lock with `clear_on_screen_lock` enabled, has dropped it. An activation of the hidden window, such as a click on the app's own tray icon, is concealed first. The script then calls `RestoreIfTicketed`, which brings the window back only when a ticket is valid and never starts polkit. Without a ticket the window stays hidden and the restore panel remains the way to authenticate. A zero grace period leaves no reusable ticket, so only the one-use ticket from an explicit unlock can skip a restore prompt, and restores ask again after it expires. `StateChanged` triggers synchronization. The setting defaults to off. A value of 0 disables it and 1 means immediate hiding. Screen-lock handling is controlled by `clear_on_screen_lock` and applies when all active graphical sessions for that user are locked.

`HiddenWindows` carries the per-app concealed count. The Shisa tray icon is a keyhole inside a ring, and the ring shows the tray state: green while no window is concealed, blue while at least one concealed window would ask for the app-lock password to restore, amber while at least one concealed app still has a valid launch ticket so a restore within the grace period would not ask, and red while shisad is offline. The green ring returns when the count reaches zero. The agent reads the tickets for a new hidden set right away and publishes the set and its ticket count in one update, so a focus-loss hide that keeps its ticket goes from green straight to amber. Every ticket read (the refresh after a `StateChanged`, the two-second poll, and the read for a new hidden set) holds the same lock across the read and the tray update that publishes the count, so a read taken before a lock or unlock cannot land after a fresher read and leave the wrong ring until the next poll. A ticket grant that brings a concealed window back holds the previous ring color until its hidden report arrives: the daemon grants the ticket and allows the window at once, while KWin keeps reporting the window hidden until it applies the change, so counting the new ticket would flash amber between the locked blue and the restored green. This covers restores, launches, autostarts, and `shisa unlock`. The hold ends with the report that drops the app, and expires on its own if the window never comes back. A confirmed drop bypasses the hold, and a revocation for the held app cancels it, so a lock during a pending restore still turns the ring blue at once. A ticket expiring is a lazy check with no signal, so the agent refreshes the hidden apps' ticket state every two seconds while a window is hidden. A blue ring is the fallback when that read fails. The tooltip names the hidden window count and how many hidden apps are password-free, and says the ticket state is unconfirmed instead of claiming the password is required when no daemon read has confirmed it. The script's check report also names the apps with a matched window it could not conceal, so a partial lock can say which app stayed visible instead of only how many windows did not match.

The window layer runs as the user. Processes under the same account can interfere with the script or window properties. The tray omits a quit action that could reveal locked windows, and idle apps remain running to preserve unsaved work.

## Lock protected apps and its result

The tray and bare `shisa lock` share the system-bus `Lock("")` contract. Success from the daemon means it revoked launch tickets and window allowance. The tray requests a fresh window check, including on repeated lock operations. The CLI requests the same check when a session bus is available. The restore panel and settings window request `VerifyLockReport`, which returns one operation's status, script generation, counts, and the app ids whose windows stayed visible. The panel shows a confirmed result with its counts, a partial result that names the apps still visible, an unconfirmed result, or a desktop without a window layer instead of a generic success. A script load acknowledgement establishes that a script ran. The window acknowledgement reports how many windows matched, how many were actually hidden, and which apps still have a visible window. A desktop without KWin's scripting interface is reported as having no window layer, so it is not mistaken for a check that failed. On a desktop with KWin, a missing or incomplete result is reported as unconfirmed, and a partial result names the apps that stayed visible. A result that needs attention stays on screen longer.

When the lock concealed at least one window, the lock result uses the locked icon. The notification is a confirmation only and carries no action, because the tray left-click is the restore entry and the notification is visible to whoever is using the borrowed desktop. Every lock produces its own result notification, so a repeated lock is confirmed again even after the previous popup has expired. The agent also reads Plasma's `Inhibited` property on `org.freedesktop.Notifications`. When the property reports that Do Not Disturb is off, the lock result reminds the owner that hidden apps still raise notifications. When the property is absent, the reminder appears once per session instead of on every lock.

Left-clicking the tray opens the restore panel. Right-clicking offers Restore windows, Lock protected apps, and settings. A disabled lock label names its reason, either that no app is protected or that shisad is offline, instead of leaving the reason in the tooltip. The tray displays the last lock result line in its tooltip. The Do Not Disturb advice stays in the notification popup, because the tooltip stays on screen after that popup has expired and should carry the result alone. The CLI can ask the agent to verify the same operation. Restoring without a prompt uses the app's ticket. Otherwise polkit authenticates first. Either way the resident script restores the original window and attempts to activate it. Before opening settings, the agent fills missing display variables from the systemd user manager's `Environment`. It launches `/usr/bin/systemd-run --user --scope /usr/bin/shisa-settings`, so an open settings or restore window survives a stop or restart of the agent instead of being killed with its cgroup. The absolute paths keep a user-writable directory earlier in PATH from supplying the launcher. `SHISA_SETTINGS_BIN` overrides the settings path for development. Arch, Fedora, and Debian install both binaries at these paths. Every request starts a new `shisa-settings` process. Tauri's single-instance plugin forwards a request to an already running window, and that callback runs on the plugin's D-Bus thread, so the new window is created through the GTK main thread. Calling GTK directly from the callback panics on the CSD shadow's CSS provider and leaves the caller with a disconnected peer. The restore panel uses the same frameless page and GTK client-side decoration shadow as the settings window. The tray disables the lock action when no app is protected, and the settings window applies the same rule.

The restore panel reads `HiddenApps` and the daemon's ticket state, so each row says whether a click restores without a prompt or asks for the app-lock password. It reloads on focus and every two seconds while visible, because a focus-loss hide can fire just after the panel takes focus and the tray or the CLI can change the hidden set while it stays open. A quiet reload clears a read error once a read succeeds and keeps the last rows, names and ticket hints when a daemon read fails but the agent still answers. When two rows share a display name, each row also shows its app id. The panel stays open after a restore and closes when nothing remains hidden. An empty panel offers Open settings and, when an app is protected, Lock protected apps. A missing session agent is reported with the command that starts it instead of a generic read error.
