# Tests and verification

- Write down a result only after the run that produced it has ended. Say what was run and what it printed. List each check that was not run as not run, and name each failure instead of calling it unrelated to the change.
- A test stops everything it starts. Stop or join every daemon, thread, and timer before the test returns. Run daemon tests on the private bus with `tests/fake-polkit`, and leave the user's configuration, `/etc`, and `/run` untouched.
- Leave a timing test room on both sides. Do not bound a test by a wall-clock duration a loaded machine can exceed, and keep fixtures far from the timeout they exercise. Reproduce a timing failure by injecting the delay, not by rerunning until it fails.

## Coverage matrix

The rows are mechanisms. The columns say where each mechanism is checked.

- **Unit and integration** runs under `cargo test --workspace`. The settings shell is outside the workspace and has its own `cargo test`.
- **Frontend tests** run under `npm test` in `gui/shisa-settings` or `node --test crates/shisa-agent/tests/*.test.mjs`.
- **Live desktop or root script** needs a real Plasma Wayland session, a real polkit agent, or sudo. These checks are manual.
- **CI** names the workflow that runs the check unattended. An em dash means that check does not exist.
- **Last verified** is the most recent run in the log below that exercised the mechanism, preferring a live, root, or installed-package run over a test-only run. A test-only date does not make the live row verified.

### Known gaps

These are the checks the matrix does not cover. A green cell is not a full verification of the mechanism.

- **No real machine without KWin.** The lock result for a desktop without KWin's scripting interface is covered by `lock_feedback_requires_all_matched_windows_to_be_concealed` only. The live result that says there is no window layer has not been seen.
- **PAM and `faillock`.** The privileged scripts use `tests/fake-polkit`. The real KDE agent, `pkttyagent`, and `pam_faillock` were last exercised on 2026-11-17. The settings page's `sudo faillock --user shisa-lock --reset` command has not been run from that page.
- **Fedora and Debian on a real KDE session.** Both packages are built in CI and their payloads were inspected, but neither has been installed on a real KDE session. Fedora SELinux denials from `fanotify_init`, `fanotify_mark`, `/proc/<pid>/exe`, or `/etc/shadow` have not been checked with `ausearch -m avc -ts recent`.
- **The sudo scripts are not in CI.** `tests/gate.sh`, `tests/auth.sh`, and `tests/settings.sh` need sudo and a real session. `test.yml` runs the workspace and frontend suites only.
- **Two apps with one display name.** `Restore.test.js` covers the id rows. No live check has two installed apps with the same display name.
- **Tray state colors.** The four states are rendered at 16x16 and 22x22 on light and dark backgrounds. The user confirmed the 0.1.5-1.1 eye tray, but the four color transitions were not exercised one by one live. The 0.1.6 keyhole-ring design and the launcher mark have no live check yet.
- **Unidentifiable exec denial.** `shisad` denies an event whose file descriptor cannot be inspected. No test seam reaches that branch.
- **`StateChanged` after a ticket-covered launch.** The policy decision is tested. The daemon's signal after that launch is not.
- **Settings language selector.** The live click that writes `ui.toml` and the tray's two-second re-read were not exercised. The screenshots were regenerated for both languages, the English one with a temporary `XDG_CONFIG_HOME` that did not touch the saved choice.
- **Live settings clicks.** The worktree's settings window was opened against the live shisad and agent and captured in Chinese and English, but Wayland input was not injected. Folds, the busy delay, toasts, the narrow layout, dark and light, and reduced motion were exercised in a browser harness against the same components. A click-through on the installed package is still the user's check.
- **Tray menu changes.** The new Restore windows item and the disabled lock labels are covered by `shisa-agent` tests. The live right-click menu was not opened.
- **Tray ticket poll.** `a_ticket_poll_keeps_the_safe_state_when_the_daemon_is_unknown` covers the decision table, but no automated test runs the two-second loop against a live agent. The live tooltip's unconfirmed branch was not exercised.
- **Package postinstall D-Bus reload.** The warning branch was exercised with a fake `systemctl`. A real upgrade where an active bus refuses a reload was not run.
- **Restore close timing.** The last-restore confirmation and the 560 ms close are covered by `Restore.test.js`. The real panel was opened empty. Restoring a hidden window from the worktree build was not exercised.

With the graphical agent stopped, `shisa unlock org.kde.kwrite` in Konsole authenticated through `pkttyagent`. `pam_faillock` counted cancellation and timeout against `shisa-lock` and left the login account unaffected.
- 2026-11-15: the service sandbox was verified. ## Running the checks

### Rust and the settings app

```sh
cargo fmt --all -- --check
cargo test --workspace
cargo clippy --workspace --all-targets
(cd gui/shisa-settings && npm ci && npm run build)
(cd gui/shisa-settings && npm test)
(cd gui/shisa-settings/src-tauri && cargo test)
(node --test crates/shisa-agent/tests/*.test.mjs)
(cd gui/shisa-settings/src-tauri && cargo build --features custom-protocol)
```

The settings crate is outside the workspace, so `cargo test --workspace` does not reach it. Its frontend rules are plain JavaScript tested with Node's built-in runner, its component tests mount the real window under jsdom with vitest, and the Tauri shell has its own tests. `npm test` runs both frontend suites. The Arch package's `check()` runs every test suite above.

CI runs the formatting check, clippy, the workspace, settings window, and KWin script suites on every push and pull request (`.github/workflows/test.yml`). It also checks formatting in the settings shell and the fuzz crate. The Tauri suite needs the WebKitGTK build stack, so it stays in the Arch package check rather than the push workflow.

The owner-check tests in `crates/shisad/tests/config_owner.rs` cannot create root-owned files as the normal user, so each re-executes itself under `unshare --user --map-root-user`. They print a skip when user namespaces are unavailable instead of passing a different check. `shisa-core`'s `files_read_for_an_account_must_be_its_own` skips when the test process runs as root, because root can read the file the test expects to be refused. The Fedora and Debian package jobs run their tests as root in the build containers.

`shisa-agent`'s test `the_manager_supplies_wayland_display_when_the_agent_lacks_it` needs a live systemd user manager that exports `WAYLAND_DISPLAY`. It skips itself in containers and CI, which have no user manager, so verify that path in a desktop session with `env -u WAYLAND_DISPLAY -u DISPLAY cargo test -p shisa-agent manager`.

### Privileged daemon scripts

After changing `shisad`, also run `tests/gate.sh`, `tests/auth.sh`, and `tests/settings.sh`. Build the release binaries with `cargo build --release` first. All three scripts require sudo, so obtain approval before running them. Use a time limit for the test daemon, use `tests/fake-polkit`, and mark only temporary files. `gate.sh` and `settings.sh` also mark `/usr/bin/kwrite`, and only `gate.sh` launches it. `auth.sh` uses temporary files only. Keep the user's open browser, terminal, and shell outside the test and keep real passwords out of scripts. Report which fanotify and polkit paths the tests exercised.

### Live desktop procedure

1. In an isolated KWin session, open a protected window and an ordinary window. Lock protected apps and verify that the protected window disappears and the ordinary window stays usable. Repeat the operation and check that the acknowledgement reflects the current state.
2. Test the no-match case and the unconfirmed result when the agent or KWin does not respond. On a desktop without KWin, check that the lock result says there is no window layer instead of calling the state unconfirmed. Check that refocusing cancels the focus-loss timer and that timer expiry hides the window. Check that the tray's Shisa ring turns amber while the hidden app's ticket is valid, that its tooltip names how many hidden apps can restore without a prompt, that Lock protected apps or ticket expiry turns it blue, and that restoring the window returns it to green. Stopping shisad should turn it red. Restore it within the app's grace period from the Shisa restore panel and from the app's own tray icon, and check that neither path asks for a password and that the window never appears before the ticket check finishes. Then let the ticket expire or run a manual lock and check that the restore panel asks for authentication while the app's own tray activation leaves the window hidden.
3. For live desktop checks, follow the [Arch packaging guide](packaging.md). Verify tray interaction, authentication cancellation, restoration of the original window and unsaved content, foreground activation, taskbar, and Overview as relevant. Real Wayland window clicks require manual input because xdotool cannot inject them.
4. When checking another settings-app build, close the window, clear its WebKit cache at `$XDG_RUNTIME_DIR/shisa-settings`, and reopen it.
5. After replacing a tray icon under the same name, restart `plasma-plasmashell.service` so Plasma drops its cached pixmaps. The agent does not need a restart unless its binary changed.

### Distribution packages

The [packages workflow](../.github/workflows/packages.yml) builds the Arch, Fedora, and Debian packages on a published release and on manual dispatch. The workflow runs the Rust workspace tests, the settings frontend tests, the Tauri tests, and the KWin script tests across its jobs: the frontend job runs the settings and KWin script suites, the Fedora and Debian jobs run the Rust workspace and Tauri suites, and the Arch job's `makepkg` check covers all four. The Fedora and Debian jobs build the binaries in `fedora:latest` and `debian:12` and package them with nfpm.

The Fedora and Debian packages still need a live KDE check and, on Fedora, an SELinux check before they are treated as verified. See [Distribution-specific verification](packaging.md#distribution-specific-verification).

### Fuzzing

The fuzz targets cover the config file parser, the desktop `Exec` splitter, and the fanotify record decoder. They need a nightly toolchain and `cargo-fuzz`, and run for a bounded time, so they are not part of `cargo test`:

```sh
cargo +nightly fuzz run config_parse -- -max_total_time=60
cargo +nightly fuzz run exec_split -- -max_total_time=60
cargo +nightly fuzz run fanotify_event -- -max_total_time=60
```

CI runs all three weekly and on demand (`.github/workflows/fuzz.yml`). See [fuzz/README.md](../fuzz/README.md) for the inputs and how to reproduce an artifact.
